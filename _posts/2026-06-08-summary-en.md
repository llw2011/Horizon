## [Research Paper Quantifies Token Consumption Patterns in Agentic Coding Workflows](https://arxiv.org/abs/2601.14470) ⭐️ 8.0/10

A new research paper titled "Tokenomics" (arXiv:2601.14470) systematically analyzes where tokens are consumed in agentic software engineering workflows, finding that input tokens dominate consumption at an average of 53.9% of total usage. As AI coding agents become mainstream development tools, understanding token consumption patterns is critical for cost optimization and architecture decisions — a single full-time agent can consume 700 million tokens per week, making efficiency a major engineering budget concern. The paper's 53.9% input token ratio appears conservative compared to practitioner reports; real-world users report ratios closer to 10:1 input-to-output, where agents read millions of tokens just to patch a single line of code. The findings suggest that mature codebases with extensive existing code drive disproportionately high input token consumption.

hackernews · Anon84 · Jun 7, 01:37 · [Discussion](https://news.ycombinator.com/item?id=48430923)

**Background**: Agentic AI refers to AI systems that can autonomously plan, execute multi-step tasks, use tools, and iterate on results without constant human supervision. In software engineering, coding agents like GitHub Copilot and Claude Code read existing codebases, plan changes, write code, and run tests in autonomous loops. Each interaction with the underlying LLM consumes tokens — the basic units of text processing — split between input tokens (context provided to the model) and output tokens (text generated by the model), with each type priced differently by providers.

## [Lathe: A CLI That Uses LLM Agents to Generate Hands-On Tutorials, Not Shortcuts](https://github.com/devenjarvis/lathe) ⭐️ 7.0/10

Lathe is a new open-source Go CLI that leverages LLM agent skills (Claude Code, Cursor, Codex) to generate source-backed, hands-on tutorials for any technical topic, requiring users to read and type code themselves rather than having AI write it for them. In an era where LLMs are primarily used to generate code and skip the learning process, Lathe represents a counter-cultural approach that uses AI agents as teaching tools — filling knowledge gaps in niche domains where quality human-written tutorials don't yet exist. Users prompt something like "/lathe build a 3D slicer in Erlang", then run `lathe serve` to spin up a local webapp with features including a scrolling table of contents, side-notes, exercises, and cited sources. The tool also supports asking questions about content, having another LLM verify that tutorial code compiles, and extending tutorials with additional parts on demand.

**Background**: Claude Code, Cursor, and Codex are agentic coding tools that can read codebases, execute commands, and generate code through natural language interfaces. The concept of 'agent skills' refers to reusable prompt-based capabilities that these tools can invoke during their workflows. The creator was motivated by personal experience learning programming through PSP homebrew tutorials, and a concern that LLM-assisted coding was replacing the hands-on learning process that builds deep understanding.

## [llama.cpp Merges Multi-Token Prediction Support for Google's Gemma 4](https://www.reddit.com/r/LocalLLaMA/comments/1tzbcyp/llamacpp_gemma4_mtp_support_merged/) ⭐️ 7.0/10

The llama.cpp project has merged Pull Request #23398, adding Multi-Token Prediction (MTP) support for Google's Gemma 4 model family. This enables speculative decoding-style acceleration for local inference of Gemma 4 models. This merge significantly improves inference speed for Gemma 4 users running models locally, as MTP can predict multiple tokens per forward pass rather than generating one at a time. It strengthens the open-source local LLM ecosystem by bringing cutting-edge inference optimizations to one of Google's most capable open model families. MTP works by introducing lightweight prediction heads that forecast multiple future tokens simultaneously, which are then verified in parallel — accepted tokens skip full autoregressive steps, yielding substantial throughput gains. The implementation is specific to Gemma 4's architecture within the llama.cpp GGML framework.

rss · r/LocalLLaMA RSS · Jun 7, 12:53

**Background**: Multi-Token Prediction (MTP) is a technique where a language model predicts several tokens ahead in one step, rather than the traditional one-token-at-a-time autoregressive approach. It is closely related to speculative decoding, where a smaller or faster model drafts multiple tokens and a larger model verifies them in batch. llama.cpp is the most widely used open-source C/C++ framework for running large language models locally on consumer hardware, supporting quantized model formats for efficient CPU and GPU inference. Gemma 4 is Google's latest family of open-weight models designed to be run both in the cloud and on local devices.
